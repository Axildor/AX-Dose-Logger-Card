**Follow-up bug fix (keyed() arrow-function):** The fade-timer-reset feature uses Lit's [`keyed()`](https://lit.dev/docs/api/directives/#keyed) directive to recreate the `.ack-flash` DOM subtree on each count change (restarting the CSS animation). The initial implementation passed an arrow function `keyed(this.ackCount, () => html\`...\`)` as the second argument, but `keyed()` expects a `TemplateResult` directly — `keyed(key, html\`...\`)`, not a function returning one. Lit rendered the arrow function's source code as a string on the button (visible as `() => b\`<div class="ack-flash...`). Fixed by removing the `() =>` wrapper in both [`daily-panel.ts`](src/components/daily-panel.ts:239) and [`drinks-panel.ts`](src/components/drinks-panel.ts:255). Build clean; dist grep confirms 0 arrow-fn-as-string patterns, 4 `ack-count-badge` matches.

**Follow-up bug fix (shouldUpdate whitelist — invisible first flash):** The first "Logged" flash sometimes failed to render visually if the button was pressed right after the fade animation finished, but the click was registered (subsequent clicks showed "2x"). Root cause: the ACK state properties (`_dailyAckActive`, `_dailyAckCount`, `_drinksAckActive`, `_drinksAckCount`, `_dailyFrozenState`, `_drinksFrozenState`) were **not in the [`shouldUpdate`](src/ax-dose-logger-card.ts:2458) whitelist**. When the fade timer expired and set `_dailyAckActive = false` + `_dailyAckCount = 0` + called `requestUpdate()`, `shouldUpdate` returned `false` (no `hass` change, no whitelisted prop changed) — the `.ack-flash` div was never removed from the DOM. A rapid re-press with `ackCount = 1` (same key as the first press) reused the stale `keyed()` instance; the CSS animation did not restart and the flash was invisible. Fixed by adding all six ACK/frozen-state properties to the `shouldUpdate` whitelist so the timer-expiry render actually fires, removing the `.ack-flash` div. The next press then creates a fresh element with a new CSS animation. Build clean; dist grep 44 matches for the ACK property names (up from 29).

**Root cause / motivation:** Each tap already fires `hass.callService('button','press')` so the backend already received one real dose per press, but the visual gave no feedback that a rapid second/third press had landed — the ACK overlay just kept showing `Logged` and the fade timer ran out unchanged. The counter is a pure UI affordance (a running tally over the ACK window), not a new backend log.

**Key Design Decisions:**
1. **Counter coupled to the ACK flag lifecycle** — `_dailyAckCount === 0` iff inactive, so there is one source of truth for "is the overlay showing a count?" and it clears itself automatically when the timer expires. No second timer, no reset-on-expire edge case. The existing single-timer architecture is preserved; only the bookkeeping inside it changes.
2. **Both buttons for parity** — the Take Pill and Log Drink buttons share an identical ACK-flash state machine, so the counter logic is mirrored on both (`_dailyAckCount` / `_drinksAckCount` + paired `_trigger*Ack` methods).
3. **`big` layout gets an `Nx` badge (user-confirmed)** — the Big-tickmark layout has no text to append the suffix to, so a small green `Nx` badge renders below the tick when count ≥ 2. Satisfies the user's "all the styles should have the 2x, 3x, 4x indicators always on" directive across all three ACK layouts. The `top`/`inline` layouts embed the count in the existing `Logged` text as `Logged 2x`.
4. **Suffix built by interpolation, no new localize key** — `${base} ${count}x` off the existing `button.ack_text` (`"Logged"`). Localizing the `x` multiplier token is English-centric; if i18n becomes a concern later a `button.ack_count_suffix` placeholder key can replace the literal `x`. For now the single `Logged` base matches the user's verbatim examples.
5. **No new config option** — the counter is always-on behaviour (matches "indicators always on"). No editor-schema change. The fade duration is still `ack_duration_ms` (default 3000), the freeze window is still `ACK_INTRO_MS` (240ms), the layout is still `ack_layout`.
6. **Disconnect hardening** — the ACK fade timers are now cancelled in `disconnectedCallback` alongside the existing freeze-timer cancellation. Previously they fired `requestUpdate` on a detached element (harmless but unclean); now cancelled for cleanliness.
7. **CSS comment backtick fix** — the new `.ack-count-badge` CSS comments initially used backticks (`` `big` ``) inside the `css` tagged template, which Lit's CSS compiler interpreted as template-literal interpolation and emitted TS1005 errors. Removed the backticks from the comments in both panels; build went clean. (The daily panel compiled clean on the first pass despite the same comment — the drinks-panel build surfaced it; both fixed for consistency.)
